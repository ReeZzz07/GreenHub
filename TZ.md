## 1. Общие сведения и цели

**1.1. Цель проекта**  
Создание Progressive Web App (PWA) платформы для C2C и B2C торговли растениями, саженцами, семенами и сопутствующими товарами. 

**1.2. Формат MVP**  
Веб-приложение без встроенного эквайринга на стороне платформы. Финансовые расчеты происходят через генерацию платежных ссылок (ЮKassa/Robokassa) или при личной встрече/по факту доставки.

**1.3. География**  
Российская Федерация (с перспективой масштабирования на страны СНГ).

**1.4. Юридические аспекты и оферта**
* Платформа выступает в роли информационного посредника (агрегатора).
* Для продавцов-физлиц: оферта на размещение объявлений с указанием ответственности за достоверность информации и соблюдение фитосанитарных норм.
* Для продавцов-юрлиц: договор возмездного оказания услуг с указанием комиссий/тарифов подписки.
* Обязательное согласие пользователей с политикой обработки персональных данных (152-ФЗ).
* Дисклеймер: платформа не несет ответственности за качество товаров и логистику, но предоставляет инструменты обратной связи и модерации.

## 2. Технологический стек и архитектура

**2.1. Frontend**  
* Next.js (React), TypeScript.
* Tailwind CSS.
* PWA (Service Workers для базового оффлайн-кэширования и установки на устройство).
* **Уточнение по оффлайну:** Кэширование статических страниц (каталог, карточки товаров) и API-ответов каталога для просмотра без соединения. Чат и оплата требуют онлайн-режима. При потере соединения — уведомление пользователя и отложенная отправка сообщений.

**2.2. Backend**  
* Node.js, NestJS, TypeScript.
* Обработка изображений: `sharp` (для генерации вотермарок, сжатия и оптимизации).
* **Очереди задач:** BullMQ + Redis для фоновых задач (ИИ-обработка, генерация вотермарок, отправка email/push).

**2.3. База данных и кэширование**  
* PostgreSQL (ORM: Prisma или TypeORM).
* Redis (управление сессиями, кэширование каталога, очереди для фоновых задач ИИ и обработки медиа).

**2.4. Хранение файлов**  
* Yandex Object Storage (S3-совместимое хранилище для фото и видео).
* **Структура бакетов:** отдельные бакеты для оригиналов и обработанных изображений (с вотермарками).

**2.5. Инфраструктура и деплой**  
* Базовый VPS (Ubuntu) с Docker и Docker Compose.
* Размещение Next.js: Vercel (бесплатный тариф) или Nginx на VPS.
* Размещение NestJS, PostgreSQL и Redis: VPS (PM2/Docker).
* **Мониторинг:** Prometheus + Grafana (базовые метрики: uptime, нагрузка CPU/RAM, количество ошибок).
* **Логирование:** Winston + ротация логов, отправка критических ошибок в Telegram-канал админа.

**2.6. Резервное копирование**
* Ежедневный бэкап PostgreSQL (через pg_dump) с хранением последних 7 дней.
* Бэкап конфигурационных файлов Docker и .env.

## 3. Ролевая модель и доступы

1. **Гость:** Просмотр каталога, карточек товаров, регистрация.
2. **Покупатель:** Поиск, использование фильтров, добавление в избранное, использование внутреннего чата, генерация и оплата по ссылкам.
3. **Продавец (Физ. лицо / ИП):** Управление объявлениями, просмотр аналитики, чат, запрос на генерацию платежных ссылок.
4. **Продавец (Юр. лицо / Питомник):** Расширенный ЛК, загрузка фитосанитарных сертификатов, массовое редактирование, управление подпиской.
5. **Модератор:** Проверка объявлений, ручная верификация документов (фитосанитарный контроль), модерация чатов.
6. **Администратор:** Полный доступ, CRUD категорий и подкатегорий, управление ролями, настройка тарифов подписок.
7. **Аналитика для продавцов (MVP):** 
   * Количество просмотров карточки товара за последние 7/30 дней.
   * Количество добавлений в избранное.
   * Количество переходов по платежной ссылке.
   * Статусы объявлений (на модерации, опубликовано, отклонено, продано).

## 4. Предметная область и Карточка товара

### 4.1. Структура категорий (CRUD для Администратора)
* **Растения:** Комнатные, Садовые. *(Подкатегории: Декоративно-лиственные, Цветущие, Суккуленты, Деревья, Кустарники и т.д.)*.
* **Посадочный материал:** Семена, Черенки, Саженцы, Мицелий.
* **Товары для ухода:** Горшки, Грунты, Фитолампы, Инструменты.

### 4.2. Атрибутика и Теги (Фильтры)
* **Биологические:** Хвойные/Лиственные, Многолетние/Однолетние.
* **Условия содержания:** Светолюбивые/Теневыносливые, Токсичность для животных.
* **Физические параметры:** Возраст, Высота/Диаметр, Тип корневой системы (ЗКС/ОКС), Тара.

### 4.3. Медиа-контент
* Галерея фотографий (высокое разрешение).
* Короткие зацикленные видео (формат MP4, до 15 сек, автоплей без звука).
* **Обработка:** При загрузке NestJS автоматически накладывает вотермарк (логотип платформы + ID продавца) через `sharp`.
* **Ограничения:** Максимум 10 фото и 3 видео на объявление. Максимальный размер файла — 5 МБ. Форматы: JPG, PNG, MP4.

### 4.4. Интеграция ИИ (NestJS Backend)
* **Распознавание:** Отправка фото в API (Plant.id или аналог). Возврат предложенного названия и базовых тегов. Пользователь подтверждает или редактирует.
  * **Fallback:** При недоступности API или ошибке распознавания — предложение пользователю ввести название вручную. Сохранение фото для последующей ручной модерации.
  * **Лимиты:** Максимум 5 запросов в час на одного пользователя (защита от злоупотреблений).
* **Генерация описания:** Отправка подтвержденных атрибутов в LLM (Qwen API или аналог). Формирование структурированного «продающего» текста с блоками «Особенности ухода», «Освещение», «Полив».
  * **Модерация ИИ-текста:** Автоматическая проверка на наличие запрещенных слов (спам, контакты, нецензурная лексика) перед публикацией.
  * **Редактирование:** Продавец может отредактировать сгенерированный текст перед отправкой на модерацию.

## 5. Пользовательские сценарии (User Flow)

### 5.1. Создание объявления (Продавец)
1. Продавец инициирует создание объявления.
2. Загружает фото/видео -> Бэкенд применяет вотермарк и отправляет в ИИ для распознавания.
3. ИИ предлагает название и теги. Продавец выбирает категорию и уточняет атрибуты.
4. Продавец нажимает «Сгенерировать описание с ИИ» -> LLM создает текст.
5. Если категория требует фитосанитарного контроля -> появляется поле для загрузки PDF/фото сертификата.
6. Объявление переходит в статус `На модерации`.

### 5.2. Модерация (Модератор)
1. Модератор просматривает список объявлений со статусом `На модерации`.
2. Проверяет медиа, текст, соответствие категории.
3. При наличии сертификата -> проверяет его визуально (ручной режим).
4. Одобрение -> статус `Опубликовано`.
5. **SLA модерации:** Время проверки объявления не более 24 часов в рабочие дни.
6. **Причины отклонения:** Шаблоны ответов для быстрого отклонения (некачественное фото, неверная категория, отсутствие сертификата, подозрительный контент).

### 5.3. Покупка и Коммуникация
1. Покупатель находит товар, пишет продавцу во встроенном чате (WebSocket + Redis).
2. Стороны договариваются о цене и логистике (зона ответственности продавца).
   * **Логистика:** В карточке товара продавец указывает регионы доставки и способы (СДЭК, Почта России, самовывоз, личная встреча). Для MVP — текстовое поле с комментариями.
3. Покупатель нажимает «Оплатить».
4. Система генерирует разовую платежную ссылку через API ЮKassa/Robokassa.
   * **Безопасность платежей:** Все платежи проходят через защищенное соединение HTTPS. Платежная ссылка одноразовая, с ограничением по времени действия (24 часа).
   * **Проверка статуса:** Вебхук от платежной системы обновляет статус заказа в базе данных. При неудачной оплате — возможность запросить новую ссылку.
5. Ссылка отправляется в чат или на email покупателю.
6. После успешной оплаты статус заказа меняется на `Оплачено`.
7. **Уведомления:** Email/Push-уведомления продавцу и покупателю об изменении статуса заказа.

### 5.4. Монетизация (Личный кабинет продавца)
* **Разовые платежи:** Оплата за публикацию (генерация ссылки).
* **Подписка для Питомников:** Выбор тарифа -> генерация ссылки на оплату рекуррентного платежа.
* **Возвраты:** Процедура возврата средств регулируется офертой платежной системы. Платформа не обрабатывает возвраты напрямую.

## 6. Требования к UI/UX и PWA

* **Mobile First:** Интерфейс проектируется преимущественно для мобильных устройств.
* **Навигация:** Нижнее таб-бар меню (Главная, Поиск, Чаты, Профиль).
* **Карточка товара:** Свайп-галерея фото/видео, крупные кнопки действия («Написать», «Купить»).
* **PWA:** Манифест для установки на главный экран, базовый Service Worker для кэширования статических ассетов и каталога.
* **Доступность (a11y):** Базовое соответствие WCAG 2.1 AA (контрастность, поддержка скринридеров, навигация с клавиатуры).
* **Производительность:** Lighthouse score не менее 90 для Performance, Best Practices, SEO.

## 7. План разработки (Roadmap MVP)

**Этап 1: Фундамент и Бэкенд (Недели 1-3)**
* Настройка VPS, Docker, PostgreSQL, Redis, Yandex S3.
* Разработка API на NestJS: Авторизация (JWT), CRUD пользователей, CRUD категорий.
* Настройка загрузки медиа в S3 с обработкой вотермарок.
* Настройка логирования и мониторинга.
* Реализация системы резервного копирования БД.

**Этап 2: Каталог и ИИ (Недели 4-5)**
* Разработка API для объявлений, фильтров, поиска (полнотекстовый поиск PostgreSQL).
* Интеграция API распознавания растений (Plant.id) с fallback-сценарием.
* Интеграция LLM (Qwen) для генерации описаний с премодерацией контента.
* Настройка очередей задач (BullMQ) для фоновой обработки.

**Этап 3: Frontend и PWA (Недели 6-8)**
* Верстка адаптивного UI на Next.js с учетом доступности (a11y).
* Реализация каталога, карточек, галерей и видео-плееров.
* Настройка PWA (манифест, service workers) с оффлайн-кэшированием.
* Оптимизация производительности (Lighthouse > 90).

**Этап 4: Коммуникация, Сделки и Модерация (Недели 9-10)**
* Реализация чата (WebSockets) с уведомлениями об оффлайне.
* Интеграция ЮKassa/Robokassa (генерация платежных ссылок, вебхуки).
* Разработка админ-панели и ЛК модератора с шаблонами ответов.
* Реализация базовой аналитики для продавцов.
* Добавление информации о логистике в карточку товара.

**Этап 5: Тестирование и Релиз (Недели 11-12)**
* Нагрузочное тестирование (k6 или Artillery), исправление багов.
* Проверка безопасности (OWASP Top 10): SQL-инъекции, XSS, CSRF, защита от брутфорса.
* Юридическая проверка оферты и политики конфиденциальности.
* Деплой на продакшн, настройка CI/CD.
* Написание документации для пользователей и администраторов.

## 9. Критерии приемки MVP

1. Все пользовательские сценарии (раздел 5) работают корректно.
2. PWA устанавливается на мобильные устройства и работает в оффлайн-режиме (кэширование каталога).
3. Интеграция с ИИ работает стабильно, есть fallback-сценарии.
4. Платежные ссылки генерируются и обрабатываются корректно, вебхуки обновляют статусы заказов.
5. Модерация объявлений проходит в течение 24 часов.
6. Lighthouse score ≥ 90 по всем категориям.
7. Пройдено базовое тестирование безопасности (OWASP Top 10).
8. Подготовлена документация для пользователей, модераторов и администраторов.
9. Юридические документы (оферта, политика конфиденциальности) согласованы и размещены на сайте.
