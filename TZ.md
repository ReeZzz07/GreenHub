## 1. Общие сведения и цели

**1.1. Цель проекта**  
Создание Progressive Web App (PWA) платформы для C2C и B2C торговли растениями, саженцами, семенами и сопутствующими товарами. 

**1.2. Формат MVP**  
Веб-приложение без встроенного эквайринга на стороне платформы. Финансовые расчеты происходят через генерацию платежных ссылок (ЮKassa/Robokassa) или при личной встрече/по факту доставки.

**1.3. География**  
Российская Федерация (с перспективой масштабирования на страны СНГ).

---

## 2. Технологический стек и архитектура

**2.1. Frontend**  
* Next.js (React), TypeScript.
* Tailwind CSS.
* PWA (Service Workers для базового оффлайн-кэширования и установки на устройство).

**2.2. Backend**  
* Node.js, NestJS, TypeScript.
* Обработка изображений: `sharp` (для генерации вотермарок).

**2.3. База данных и кэширование**  
* PostgreSQL (ORM: Prisma или TypeORM).
* Redis (управление сессиями, кэширование каталога, очереди для фоновых задач ИИ и обработки медиа).

**2.4. Хранение файлов**  
* Yandex Object Storage (S3-совместимое хранилище для фото и видео).

**2.5. Инфраструктура и деплой**  
* Базовый VPS (Ubuntu) с Docker и Docker Compose.
* Размещение Next.js: Vercel (бесплатный тариф) или Nginx на VPS.
* Размещение NestJS, PostgreSQL и Redis: VPS (PM2/Docker).

---

## 3. Ролевая модель и доступы

1. **Гость:** Просмотр каталога, карточек товаров, регистрация.
2. **Покупатель:** Поиск, использование фильтров, добавление в избранное, использование внутреннего чата, генерация и оплата по ссылкам.
3. **Продавец (Физ. лицо / ИП):** Управление объявлениями, просмотр аналитики, чат, запрос на генерацию платежных ссылок.
4. **Продавец (Юр. лицо / Питомник):** Расширенный ЛК, загрузка фитосанитарных сертификатов, массовое редактирование, управление подпиской.
5. **Модератор:** Проверка объявлений, ручная верификация документов (фитосанитарный контроль), модерация чатов.
6. **Администратор:** Полный доступ, CRUD категорий и подкатегорий, управление ролями, настройка тарифов подписок.

## 4. Предметная область и Карточка товара

### 4.1. Структура категорий (CRUD для Администратора)
* **Растения:** Комнатные, Садовые. *(Подкатегории: Декоративно-лиственные, Цветущие, Суккуленты, Деревья, Кустарники и т.д.)*.
* **Посадочный материал:** Семена, Черенки, Саженцы, Мицелий.
* **Товары для ухода:** Горшки, Грунты, Фитолампы, Инструменты.

### 4.2. Атрибутика и Теги (Фильтры)
* **Биологические:** Хвойные/Лиственные, Многолетние/Однолетние.
* **Условия содержания:** Светолюбивые/Теневыносливые, Токсичность для животных.
* **Физические параметры:** Возраст, Высота/Диаметр, Тип корневой системы (ЗКС/ОКС), Тара.

### 4.3. Медиа-контент
* Галерея фотографий (высокое разрешение).
* Короткие зацикленные видео (формат MP4, до 15 сек, автоплей без звука).
* **Обработка:** При загрузке NestJS автоматически накладывает вотермарк (логотип платформы + ID продавца) через `sharp`.

### 4.4. Интеграция ИИ (NestJS Backend)
* **Распознавание:** Отправка фото в API (Plant.id или аналог). Возврат предложенного названия и базовых тегов. Пользователь подтверждает или редактирует.
* **Генерация описания:** Отправка подтвержденных атрибутов в LLM (Qwen API или аналог). Формирование структурированного «продающего» текста с блоками «Особенности ухода», «Освещение», «Полив».

## 5. Пользовательские сценарии (User Flow)

### 5.1. Создание объявления (Продавец)
1. Продавец инициирует создание объявления.
2. Загружает фото/видео -> Бэкенд применяет вотермарк и отправляет в ИИ для распознавания.
3. ИИ предлагает название и теги. Продавец выбирает категорию и уточняет атрибуты.
4. Продавец нажимает «Сгенерировать описание с ИИ» -> LLM создает текст.
5. Если категория требует фитосанитарного контроля -> появляется поле для загрузки PDF/фото сертификата.
6. Объявление переходит в статус `На модерации`.

### 5.2. Модерация (Модератор)
1. Модератор просматривает список объявлений со статусом `На модерации`.
2. Проверяет медиа, текст, соответствие категории.
3. При наличии сертификата -> проверяет его визуально (ручной режим).
4. Одобрение -> статус `Опубликовано`.

### 5.3. Покупка и Коммуникация
1. Покупатель находит товар, пишет продавцу во встроенном чате (WebSocket + Redis).
2. Стороны договариваются о цене и логистике (зона ответственности продавца).
3. Покупатель нажимает «Оплатить».
4. Система генерирует разовую платежную ссылку через API ЮKassa/Robokassa.
5. Ссылка отправляется в чат или на email покупателю.
6. После успешной оплаты статус заказа меняется на `Оплачено`.

### 5.4. Монетизация (Личный кабинет продавца)
* **Разовые платежи:** Оплата за публикацию (генерация ссылки).
* **Подписка для Питомников:** Выбор тарифа -> генерация ссылки на оплату рекуррентного платежа.

## 6. Требования к UI/UX и PWA

* **Mobile First:** Интерфейс проектируется преимущественно для мобильных устройств.
* **Навигация:** Нижнее таб-бар меню (Главная, Поиск, Чаты, Профиль).
* **Карточка товара:** Свайп-галерея фото/видео, крупные кнопки действия («Написать», «Купить»).
* **PWA:** Манифест для установки на главный экран, базовый Service Worker для кэширования статических ассетов и каталога.

## 7. План разработки (Roadmap MVP)

**Этап 1: Фундамент и Бэкенд (Недели 1-3)**
* Настройка VPS, Docker, PostgreSQL, Redis, Yandex S3.
* Разработка API на NestJS: Авторизация (JWT), CRUD пользователей, CRUD категорий.
* Настройка загрузки медиа в S3 с обработкой вотермарок.

**Этап 2: Каталог и ИИ (Недели 4-5)**
* Разработка API для объявлений, фильтров, поиска (полнотекстовый поиск PostgreSQL).
* Интеграция API распознавания растений (Plant.id).
* Интеграция LLM (Qwen) для генерации описаний.

**Этап 3: Frontend и PWA (Недели 6-8)**
* Верстка адаптивного UI на Next.js.
* Реализация каталога, карточек, галерей и видео-плееров.
* Настройка PWA (манифест, service workers).

**Этап 4: Коммуникация, Сделки и Модерация (Недели 9-10)**
* Реализация чата (WebSockets).
* Интеграция ЮKassa/Robokassa (генерация платежных ссылок).
* Разработка админ-панели и ЛК модератора.

**Этап 5: Тестирование и Релиз (Недели 11-12)**
* Нагрузочное тестирование, исправление багов.
* Деплой на продакшн, настройка CI/CD.
